    HTTPS and Test Servers

    Q:  My app talks to a server over HTTPS. The production server uses a certificate issued by a trusted certificate authority, so everything works just fine. However, when my app talks to my test server, which uses a self-signed certificate, things fail. How can I test my app against my test server?

    A: There are two approaches you can take here, discussed in the sections below.

    Test Certificate Authority

    Our recommended approach is that you do this by setting up a test certificate authority (CA). The basic idea is:

    1. Create your own CA for testing

    2. Use that CA to create a digital identity for your server

    3. Install that CA’s root certificate on your test devices

    This approach has some important benefits:

    • It works with all OS subsystems, whereas the alternative, customising HTTPS server trust evaluation, relies on specific hooks that aren’t supported by all subsystems

    • It does not require you to write any code

    • Because there’s no test code in your app, there’s no chance of you accidentally shipping an app to customers with that test code enabled

      Warning: Do not discount this risk. A number of developers, including some household names, have had to publish an emergency update to their app because they accidentally shipped it with server trust evaluation disabled. In some cases this problem was not found for years, exposing their customers’ data for all that time.

    • Your testing is more realistic because it uses exactly the same code path as your production app

    With regards step 1, if you don’t have experience running a CA you can take advantage of the facilities built in to macOS; see Creating Certificates for TLS Testing for the details.

    With regards step 3, there are various ways to install your test CA’s root certificate on your test device. For detailed instructions on how to do this, see Installing a CA’s Root Certificate on Your Test Device, below.

    Customising HTTPS Server Trust Evaluation

    If you’re unable to use a test CA, your only alternative is to customise HTTPS server trust evaluation to ignore the fact that you’re connecting to an insecure server. There are two basic steps here:

    1. You must override the default HTTPS server trust evaluation. Techniques for doing this are described in HTTPS Server Trust Evaluation.

    2. If your app uses a high-level HTTPS API — NSURLSession, NSURLConnection, or anything layered on top of those — you must disable App Transport Security (ATS) for your server. See the “NSAppTransportSecurity” section of the Information Property List Key Reference for details.

    Warning: You must remove these changes in the production build you ship to users. Failure to do so could compromise the security of your app.

    Installing a CA’s Root Certificate on Your Test Device

    The process for installing a CA’s root certificate on your test device varies by device type. The following sections cover the most common cases.

    Important: The focus here is on testing during app development. If you want to install a custom CA for other reasons — for example, if you’re managing devices for a large enterprise — there are other, better approaches you can take (configuration profiles, MDM and so on). These approaches are supported by AppleCare and described on their site.

    macOS

    To install a CA’s root certificate on macOS, use the Keychain Access utility to add the root certificate to the System keychain and then explicitly mark it as trusted.

    iOS Device

    There are three common ways to install a CA’s root certificate on an iOS device for testing purposes:

    • Put the .cer file on a web server and navigate to it in Safari. iOS will then ask you whether you want to install and trust that root certificate.

    • Attach the root certificate to an email and then email it to yourself; when you open the attachment, iOS will ask you whether you want to install and trust that root certificate.

    • Use Apple Configurator to create a configuration profile that includes the root certificate and then drag that configuration profile to the device in the main Apple Configurator window. In most cases you’ll need to complete the install process on the iOS device itself.

    Important: Regardless of how you install the root certificate you must specifically enable it in Settings > General > About > Certificate Trust Settings.

    iOS Simulator

    The quickest way to install a CA’s root certificate on the simulator is to drag the root certificate to the main simulator window. This will kick off the same install process that you see on the device.

    Alternatively, you can put the root certificate on a web server and then navigate to it in Safari, as you would on a real device.

    Important: As in the on-device case, you must specifically enable the root certificate in Settings > General > About > Certificate Trust Settings.

    watchOS Device

    watchOS can run network requests via the paired iPhone or directly on the Apple Watch. For your CA’s root certificate to be effective in all circumstances it must be installed on both devices.

    When you install a root certificate on your iPhone (using one of the processes described above), iOS will ask you whether you want to install it on iPhone or Apple Watch. You must run through this process twice, once to install the certificate on your iPhone and again to install it on your Apple Watch.

    Important: iOS 10.3 and later have a bug that causes them not to display this alert (r. 34652068) . Until that bug is resolved you will not be able to install your root certificate on the Apple Watch. You can still test on Apple Watch as long as the paired iPhone is available to run network requests.

    watchOS Simulator

    The watchOS simulator always runs network requests via the paired iPhone simulator, so installing a CA’s root certificate on that paired simulator is sufficient to support watchOS testing.

    tvOS Device and Simulator

    To install a CA’s root certificate on a tvOS device or simulator, do the following:

    1. Put the .cer file containing the root certificate on a web server

    2. Navigate to Settings > General > Privacy and select Share Apple TV Analytics

    3. Press the Play/Pause button on the remote; this brings up a screen that lists the installed profiles along with an Add Profile option at the top

    4. Choose Add Profile

    5. Enter the URL of the profile and follow the on-screen instructions to complete the install process

    Important: As with iOS, you must specifically enable the root certificate in Settings > General > About > Certificate Trust Settings.
